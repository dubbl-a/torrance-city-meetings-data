# torrance-city-meetings-data

## What this is

The public documentation home for a read-only Postgres dataset of Torrance City
Council decisions: meetings, agenda items, motions, per-member votes and seats,
hosted on Neon and read by anyone who asks the maintainer for the connection
string. This repository holds documentation, a schema file and example queries.
It holds no application code and no data.

## Core principle

Readers are not Claude Code users. Everything reader-facing here is
stack-agnostic: plain SQL, standard Postgres clients, ordinary prose. Nothing in
`README.md`, `DATA-DICTIONARY.md`, `queries/` or `CHANGELOG.md` mentions Claude,
house rules, npm scripts or the private repository that generates this content.
The maintainer tooling (`CLAUDE.md`, `house.json`, `.house/`, `.claude/`) is the
only exception, and the README says in one sentence that readers can ignore it.

## Generated content

`schema.sql` is generated by the publisher in the private torrance-watch
repository, which applies that DDL to the database before each publish run. Hand
edits to it are not applied to the database and are lost on the next generation.
Fix the publisher, not the file. The row counts in `README.md` and
`CHANGELOG.md` are likewise read off the live database rather than written from
memory; re-run the count before changing one.

## Stack

No stack. Markdown, SQL and a GitHub issue template. There is no package
manifest, no build and no test suite, which is why `check:docs` and
`check:house` are not wired as npm scripts here: run `node .house/check.mjs`
directly.

Topic-specific rules load only when a matching path is open. Grep

## Build-time guards

`node .house/check.mjs` is the only gate. It resolves every backticked token in
a scanned document against the repository, so a claim about a table, a column or
a query file fails the run on the commit that makes it wrong. Run it before
opening a pull request.

## What not to do

- Don't put a password, a connection secret or a Neon account id in this
  repository. The README shows the URL shape with a placeholder and says how to
  ask for the real one.
- Don't hand-edit `schema.sql`.
- Don't use em dashes in body copy. Use commas, parentheses or a sentence break.
- Don't publish a raw motion count, and don't read a NULL `vote_value` as a no
  or an absence. Both caveats are in the README and the data dictionary because
  both produce a confidently wrong number.
- Don't add a query to `queries/` without running it against the live database
  first, and without a header comment saying what it answers and where it
  misleads.
- Don't characterise a member, a vote or a decision. This dataset describes what
  the record says and stops there.

## Contributing workflow

- Branch and open a pull request for every change, even solo work and even a
  one-line fix. Never commit directly to `main` after the initial import.
- Ship the README, CLAUDE.md and changelog edit a change requires in the same
  pull request, not as a follow-up.
- Git state is shared across sessions: check the current branch immediately
  before every commit and push.
- Preview is not applicable here, since nothing renders. Run
  `node .house/check.mjs` instead, and run any query you changed.

## Deviations from house

Five modules are disabled: `data-pipelines`, `database`, `deployment`, `testing`
and `llm-output`. This repository has no application code, no database it owns,
nothing to deploy, no test suite and no LLM output surface, so each of those
modules would load rules scoped to paths that do not exist. Recorded in
`house.json`'s `deviations` array, dated, with the why; `house.json` is the
source of truth and this section mirrors it.

## Who this is for

Anyone who wants to answer a question about what the Torrance City Council
decided and would rather query the record than read a hundred PDFs: residents,
reporters, students, and other civic projects.
